# CLAUDE.md

Instructions for Claude when working in this repository. Read this **before** writing or editing code.

## Project

**North & Refine** — the marketing site for a design studio whose clients are medical aesthetic and cosmetic surgery practices. This is the studio's own shop window, so it has to look like the work we'd sell to a cosmetic surgeon. It is **SEO- and schema-led** by design.

- **Framework:** Next.js 15 (App Router) + React 19 + TypeScript
- **Styling:** Tailwind 3 + a custom design-token system in `src/app/globals.css`
- **Content:** MDX collections read from `content/` at build time (no CMS) via `gray-matter` + `next-mdx-remote/rsc`
- **Hosting:** Netlify (`@netlify/plugin-nextjs`)
- **Fonts:** **ONE TEXT FACE — Instrument Sans** (2026-07-14, the client's call: "make all headings and text Instrument Sans"; the Saol serif wasn't working). `layout.tsx` loads it as `--font-sans` and **aliases `--font-display` to it on `<html>`**, so the ~27 heading/body rules in globals.css that read either variable all resolve to Instrument Sans with no per-rule edit. Two faces survive in narrow, real roles: **Saol Display** (`--font-saol`) is the **ACCENT-WORD device only** — an `<em>` inside a display-tier utility ("Practices that patients *trust*."), one word or short phrase per statement; and **Geist Mono** (`--font-geist-mono`) is **THE KICKER VOICE**, which `.overline` consumes (2026-07-20, "unify the kicker"), so every tracked-caps kicker sitewide is one face. ⚠ **This supersedes the TWO-FONT HOUSE note that stood here until 2026-08-02**, which claimed Saol carried every heading tier, that Dia carried body and UI, and that the mono was retired from the brand. All three were false: the /stylesheet audit found the page and this file describing a house `layout.tsx` had not loaded for nearly three weeks. Two consequences that matter — the licence blockers are GONE (Dia and Saol trials are not shipping, so the layout font block commits normally), and **heading hierarchy is no longer size-only**: the house face has real weights, which is what makes `.form-title`'s weight-led register legal. Headings still don't take `font-medium`; that is a taste rule now, not a technical one.
- **Source of truth for the brand:** `src/app/globals.css` — all design tokens live there; rendered live at **`/stylesheet`**, which was RESTRUCTURED 2026-08-02 into four tiers: **01 Principles** (the canon that decides before anything is drawn) → **02 Atoms** (colour, type, space, radius, material) → **03 Molecules** (the compositions that repeat) → **04 Components** (every component, Storybook-style, with props and the routes that render it). It has a sticky left rail of anchor links; each tier is its own file under `src/app/stylesheet/sections/`, and the shared documentation primitives are in `_ui.tsx` (⚠ for that page ONLY — never import them into the site). The rebuild followed an audit that found **32 statements on the page contradicted by the code**, so the standing rule now has teeth: **add a token to globals.css and you add it to /stylesheet in the same change**, and anything unused is either DELETED or explicitly tagged PARKED with the note that parks it. Nothing on that page is aspirational.
- **Direction:** dark / premium agency. Deep neutral black (`ink`), bone off-white, one restrained champagne accent — plus a bright `ember` signal at 60-30-10 doses (live dots only).

## How to use this file

Before writing markup or styles, scan **Design tokens** and **Components**. If a token, utility class, or component already exists for what you're building, use it — don't write parallel implementations. If nothing fits and you're about to introduce a new token, **ask first**. The cost of asking is one round-trip; the cost of drift is months.

### Typography utilities (use these, never raw `clamp()`/inline `fontFamily`)

Fluid modular scale, one `clamp()` per class. Body is fluid 14→16px (mobile→desktop); `.body-sm` (13→14) is the secondary/meta tier.

`.display-mega` · `.display` · `.heading-xl` · `.heading-part` · `.statement` · `.heading-lg` · `.heading-md` · `.heading-sm` · `.form-title` (15px/600 — FORM SECTION TITLES, added 2026-08-01: see THE UI REGISTER below) · `.body-xl` (16→21px, THE LARGE LEDE — the centred manifesto hero + the ContactCTA close subtitle; one step above `.body-lg` (which stays the left/split hero lede), added 2026-07-13 to retire the ad-hoc `md:text-[21px]`) · `.body-lg` (lede) · `.body` · `.body-sm` (secondary/meta) · `.card-title` (sans card captions) · `.body-reading` (long-form prose) · `.blockquote` (DEPRECATED) · `.overline` (kicker) · `.label` · `.fineprint` · `.stat` · `.index-num` · `.nav-link` · `.cta-label` · `.wordmark-giant` (the footer's cropped NORTH)

- **THE LADDER (decided 2026-07-09)** — pick sizes by REGISTER, not taste: `.display-mega` = the ODOMETER numeral (the /services scroll-index window; its old homepage-masthead use RETIRED 2026-07-16 — the three-section hero's H1 sits in a 5-col column, so it takes `.display` like every masthead) → `.display` = the MASTHEADS + the LEDGER ROWS (2026-07-16, hero-cohesion pass: every H1 sitewide — the homepage's three-section hero and every interior split hero — plus the What-we-do service titles, their first live use 2026-07-11) → `.heading-xl` = the MOMENTS (DETAIL-page H1s — /work/[slug], /blog/[slug] article headers; on the homepage: the studio statement, the ContactCTA close) → `.heading-part` = the PART TITLES (32→62px, rung added 2026-07-10: the homepage COLLECTION HEADS — "Practices we've refined", "Notes from the studio" — were too small at lg, tied to the work-card names below them, and too big at xl; part titles introduce a collection, one register below a moment) → `.statement` = the QUOTE register (testimonial quotes) → `.heading-lg` = the SIGNPOSTS (interior-page section H2s) → `.heading-md`/`.heading-sm` = items (cards, steps) → `.card-title` = THE CARD CAPTIONS (2026-07-11: work-card client names + blog teaser titles share one 17→22px SANS register — card titles are captions to their images, not headings, so they left the Saol ladder for the Dia meta voice; no `<em>` accent in sans). A list item must never outrank OR TIE its section's head; a signpost must never shout like a moment.
- **THE UI REGISTER — `.form-title` (2026-08-01, client on the Start-a-project form: "titles on the form smaller and bolder", "excessive borders under the titles should be removed").** A form's section titles are FURNITURE the reader scans, not editorial moments, so they sit OFF the ladder: 15px at **weight 600**, sentence case, **no rule under them**. It leads by EMPHASIS rather than size — the one place weight does the work — which is legal because the house face is Instrument Sans with real weights (see `layout.tsx`); the size-only rule above belongs to the display family, which ships one upright weight. The two rejected drafts are the argument for it: `.overline` read as eyebrow text ("I want actual titles"), `.heading-sm` read as an editorial heading dropped inside a form. **Forms only** — a page or section head never takes it. `StartProjectForm` is the live consumer; `ContactForm` has no sections to title (three fields, `.overline` labels), so if it ever grows any, they take this.
- `.blockquote` is DEPRECATED (2026-07-09) — a sans-era relic; quotes use `.statement` (Saol). It survives in globals only for the /mockups archive.
- **BASELINES LOCK (decided 2026-07-10)** — side-by-side type aligns on baselines, never box edges, and never with eyeballed `pt-*` nudges. Wherever a TITLE sits left and a LINK sits right, the link locks to the HEADING'S baseline — via FIRST baseline (`items-baseline`) when the heading leads its block (industries index rows, FAQ summaries, prose-beside-statement pairs, CTA kicker+statement, CTA pair labels, folio arrows+counter) or LAST baseline (`[align-items:last_baseline]`, declared after an `items-end` fallback for old browsers) when the heading closes its block or the link should sit on its bottom line (section header rows with kicker+H2, the service rows, Kind words' image-bottom-on-attribution). Print rules the page; boxes are invisible.
- `.overline` is BONE BY DEFAULT (2026-07-09, reversing the old champagne rule — the type system is TONAL; gold at 11px tracked caps reads brassy). On light sections override with `text-ink-mute` (the AA on-light meta tint) — or `text-clay` where the warm brand tint is wanted on the KICKER specifically (the tracked-caps ornament exception noted in the colour table; clay is sub-AA so never use it for on-light meta that must be read: dates, labels, body → `text-ink-mute`/`text-ink-dim`). It also collides with Tailwind's `overline` text-decoration utility — an **unlayered override at the end of globals.css** disables the decoration. Don't remove it or move it into a @layer.
- **Heading-group spacing:** put the overline and heading as direct siblings and add `.from-overline` to the heading (margin scales with the heading). Use `.lede` on the subtitle. **Never** set these gaps ad-hoc with `mt-*`/`mb-*`.
- **THE MASTHEAD GRAMMAR — the kicker is INSIDE the H1 (2026-08-05, client: "the overline on each hero is actually part of the H1, but styled as an overline, and it mimics the page name").** A masthead is ONE SENTENCE IN TWO REGISTERS: the page names itself, then says what it does for the reader. So a masthead H1 is `<h1 class="display with-overline"><span class="overline">Services</span>{" "}<span>Websites that <em>just</em> work.</span></h1>`, and the contract is **kicker = THE PAGE NAME · display line = a FEATURE-BENEFIT STATEMENT that must not restate it**. Every masthead H1 now reads "Services Websites that just work." to a crawler and a screen reader both, which on an SEO-led site is the page's strongest signal finally carrying the page's own name. Three consequences worth knowing. (1) `.with-overline` is FLEX, and the gap is a flex `gap` (0.7em; 0.35em at display tier) because `gap`'s em resolves against the heading's own font-size — the identical number `.from-overline` used, so every masthead measured pixel-identical before and after; a margin on the kicker span would resolve against its 11px and vanish. (2) The two spans need a literal `{" "}` between them or the H1 extracts as "PrivacyWhat we collect". (3) A **DETAIL PAGE NAMES ITSELF, not its section** — /services/web-design's kicker is "Web design & build", not "Services". EXCEPTIONS: the **homepage**, which has no page name and states the offer instead; and **ARTICLE HEADERS** (/work/[slug], /blog/[slug]), whose kicker is metadata about the piece ("Aesthetics · 2026") and stays a sibling on `.from-overline` — the test is whether the kicker still makes sense read aloud as the heading's first words.
- h1–h6 default to Saol at 400, tight tracking (they have since 2026-07-05 — an older "sans at medium" note here was wrong). Don't override per-element without reason.

### Buttons — a FOUR-TIER hierarchy (2026-07-09). Always compose; never hand-roll a pill CTA.

`light`/`dark` = the **background the button sits on**, not the button's colour. **Gold is the hover**: every tier's hover state is where champagne lives (per the interactions-only colour rule) — never its resting state.

1. **Flagship** — `.btn` + primary variant + `.btn-arrow` (label left, circular ↗ chip: `<span class="btn-arrow-chip" aria-hidden>↗</span>`). ONE per view. ⚠ **DOWN TO ONE CONSUMER, the ContactCTA close band (2026-08-06)** — it lost the homepage hero when every hero primary became `.btn-glass`, so the loudest tier now only ever appears at the FOOT of a page, never the top: the hero invites, the close asks. Single-consumer token, flagged on the same terms as `.btn-secondary-light` and `.heading-part`. The nav carries a `.btn-sm` PRIMARY (stepped up from secondary 2026-07-31, client: "like a primary button" — a tier-2 pill, no arrow chip, so still never a second flagship in the first viewport). On mobile the same pill rides the BAR beside the burger (out of the drawer, client's call); every "Start a project" pill sitewide opens the FORM OVERLAY (see `StartProjectOverlay`). Pill labels never wrap (`white-space: nowrap` on `.btn`, same day — a folded pill reads broken). Hover: pill → champagne-soft, chip → champagne, arrow leans NE.
2. **Primary pill** — `.btn-primary-dark` (solid bone) / `.btn-primary-light` (solid ink). Hover → champagne-soft fill.
3. **Secondary outline** — `.btn-secondary-dark` / `.btn-secondary-light`. Hover → **champagne rim** + faint champagne wash. It must NEVER fill solid on hover (that made it impersonate the primary — fixed 2026-07-09).
4. **Ghost** — `.btn-ghost` + explicit text colour, arrow as `<span aria-hidden>→</span>`. The tertiary workhorse: every section's onward link ("All work →", "Our story →", "Read more →"). Hover: gap opens, arrow turns champagne. Never dim the whole link on hover — fading reads as disabled.

- `.btn-sm` size modifier. `.btn` padding is **20/40** (2026-07-24, client: "more padding on buttons" — was 16/32; the vertical sits on the 4px half-step, the horizontal on the 8px grid). `.btn-sm` keeps 16/24.
- `.btn-glass` — the GLASS PILL, and **THE HERO PRIMARY on every hero sitewide (2026-08-06,** client: hero CTAs "should be glass as primary and text as secondary"; it was a /services-only trial from 2026-07-24). The card-glass surface as a button — 9% bone fill + backdrop blur + 25% bone rim, so the warm ground reads through it. DARK grounds only, and that constraint is exactly why it belongs to heroes: **a hero is the one slot with a LIT ground behind the button** (the warm `HeroGlow`), so the blur has something to do. Below the fold the ground is flat and the same pill is glass over nothing — `.btn-primary-dark` remains the sitewide primary everywhere else; a LIGHT hero falls back to the solid ink pill (9% bone on bone is a smudge). **THE HERO PAIR is fixed: `.btn-glass` primary + `.btn-ghost` second action, on one baseline.** Hover follows the gold rule (champagne rim + 8% wash). ⚠ Known exception, raised and signed off: the HOMEPAGE hero's CTA row overlaps its device mock-ups, so that one pill blurs black hardware rather than glow and reads quieter than the nav pill above it; if it's ever revisited the fix is the CAUSE (drop the device row), not a special-case pill.
- `.live-dot` — the pulsing ember availability signal (PARKED: currently unused — it was the nav availability badge, removed 2026-07-04; the utility + swatch remain in the system).

### Layout helpers

- `.shell` — standard max-width **1600px** container with responsive padding (widened 1280 → 1400 → 1520 across 2026-07-04→10, → 1600 with eased padding `clamp(1.5rem, 3vw, 3rem)` on 2026-07-23 — on a MacBook Air the cap never binds, so the padding ease is what widens it there; don't re-narrow below 1400 without the client asking). The **content grid** — use on all body sections so copy keeps a comfortable measure. The **NAV also sits on it** now (2026-07-13, client's call): its content shares this one rail with every page's content, so the logo/links/CTA align with the hero, sections and footer (the nav's bg + full-bleed border stay on a wider full-width wrapper). The homepage HERO also sits on it (one left rail with everything below — a shell-wide hero was trialled and read as two pages sharing a scroll). |
- `.shell-wide` — open, near-full-width container (max 1760px, lighter padding). **Heroes only**, with one sanctioned exception: the work/[slug] article uses it as the IMAGE canvas — figures span it (full or 5+5 pairs) while kickers/copy stay grid-indented to a reading measure. Everything else sits on `.shell` so content shares one max width. (A full edge-to-edge homepage was built and rolled back 2026-07-09 — the deck layout won; don't reintroduce without asking.)
- `.grain` / `.grain-light` — **THE ONE MATERIAL (2026-07-24).** Both need `position: relative` + `overflow-hidden` on the parent and `z-10` on content above. `.grain` is the 4% film overlay for DARK grounds; `.grain-light` is the same noise at 5% with `mix-blend-mode: multiply` for BONE/CREAM grounds, where it reads as paper tooth (multiply darkens the stock; the dark overlay's normal blend would wash it out). **Every section on the site now carries one or the other** — grain was dark-only until the client reported the backgrounds "feel like there's a disconnect visually", which was exactly this: every dark surface was a material and every light one a flat paint. **The answer to that disconnect is TEXTURE, not gradient** — a blurred bloom on bone reads as a stain (paper is expected to be even; the 2026-07-10 gold band was reverted for the same reason) and low-contrast light grounds band, which the grain's dither suppresses. Think of it as: **grain is the material and is constant; glow is light and decays.** ⚠ **`overflow-hidden` KILLS `position: sticky`** — an overflow-hidden ancestor becomes the sticky element's scroll container, so the pin silently stops working and the element just scrolls away. `.grain` does NOT need the clip (its `::before` is `inset-0`, so nothing can overflow); only the GLOW blobs do. On any section containing sticky content (the /services rolling numeral — since 2026-08-07 the site's ONLY sticky element, the homepage manifesto having unpinned that day) put the glow in an absolutely-positioned `overflow-hidden` layer that is a **SIBLING of the sticky content, never its ancestor** — and leave the section itself unclipped. This regressed the /services odometer twice on 2026-07-24 (once adding `SectionGlow`, once in the grain sweep) before the client caught it. Never add a second glow to "continue" a hero blend down a page — let the glow decay and keep the grain continuous. /work's hero `grain={false}` was removed in the same pass (it existed only because the grid below was ungrained; both sides now match).
- `.frame` — media wrapper (relative, overflow-hidden, ink-raised background, **rounded-plate since 2026-08-01** — the imagery sweep; every framed plate on the site curves together).
- `animate-float-slow` / `animate-float-slower` — floaty hero elements (orbs, glass chips); stagger with inline `animationDelay`. **ENTRANCES FADE IN PLACE (2026-07-10):** load-ins use `opacity-0 animate-fade-in` + delays; scroll sections use `.reveal` (now a pure 1.1s fade). The 16px rise (`animate-fade-in-up`, the old `.reveal` translate) is RETIRED from the brand — sliding in is a screen idiom, ink develops where it sits; `fade-in-up` survives only in the /mockups archive. A global reduced-motion guard at the end of globals.css snaps all animations to their end state.
- `.reveal` — scroll-reveal entry. Add the class; stagger with inline `style={{ transitionDelay: "120ms" }}`. The global `<Reveal />` (in the root layout) observes them. Respects reduced-motion.

### Surfaces & frames (tech-luxury direction)

- **BLENDING DARK SECTIONS — THE SHARED CANVAS (the rule, settled 2026-07-24).** When the client asks for the hero gradient to "fade/blend through" into following sections ("they need to almost be one"), there is ONE sanctioned technique: **wrap the sections in a single `relative overflow-hidden` div that owns the whole ground** — warm base (`bg-[#16110C]`), one `<HeroGlow>`, `grain`, extra blobs placed per-band as needed, and a foot strip fading to `var(--ink)` (#110E0A since the 2026-07-31 re-tone) before the next normal section. Children render groundless on it (PageHero takes `ground={false}`). Built as **`SharedCanvas`** (named AboutSharedCanvas until the homepage became the second consumer, 2026-08-07 — nothing in it was ever /about-specific). Live examples: /about (hero → mock-up ream → Who-we-are) and the homepage (the hero alone — the manifesto passed through the canvas for half a day before becoming the BONE ACT, whose designed cuts need no canvas; a one-child canvas is still the right wrapper wherever a glow, grain and a resolving foot must travel together). **Do NOT try to blend two separately-grounded sections by colour-matching their boundary** — the 2026-07-23 "seam contract" (hero foot fades to anchor `#14100B`, next section's `SectionGlow` wash resumes from it) shipped and FAILED TWICE on /about: any residual mismatch (glow still bright at the foot, the 4% grain lift on one side only, a clipped blur restarting warmth below the line) reads as a cut. `SectionGlow` + the PageHero anchor strip remain live on /work, /services and /contact where the hero foot is already dark and the join currently passes; if a line is ever reported there, the fix is converting that page to the shared canvas, not more seam-tuning.

## Content & SEO architecture

This is the core of the site — treat schema and metadata as first-class.

- **Site facts:** `src/lib/site.ts` (`SITE`, `NAV`, `absoluteUrl`). Change brand facts here, never inline. **Set the real domain in `SITE.url` before launch.**
- **Schema builders:** `src/lib/schema.ts` → `organizationSchema`, `websiteSchema`, `breadcrumbSchema`, `articleSchema`, `caseStudySchema`, `serviceSchema`, `faqSchema`. Emit via `<JsonLd data={...} />`. Org + WebSite go once site-wide (root layout); every page adds its own breadcrumb; detail pages add Article/CreativeWork; Services/Pricing/Industries add Service + FAQ.
- **Metadata:** root `layout.tsx` sets defaults + title template + OG/Twitter. **Every page must export its own `metadata`** with a real `description` and `alternates.canonical`. Empty descriptions are a bug on this site.
- **Sitemap / robots:** `src/app/sitemap.ts` + `src/app/robots.ts`, driven by the content collections + `INDUSTRIES`. `/stylesheet` is intentionally excluded and noindexed.

### Collections

Generic factory in `src/lib/content.ts` (`createCollection`), with two instances:

- **Journal** (`src/lib/journal.ts`, `content/journal/*.mdx`) — the SEO blog. Categories enforced. Route: `/journal` + `/journal/[slug]`.
- **Work** (`src/lib/work.ts`, `content/work/*.mdx`) — case studies, with client/sector/services/metrics. Route: `/work` + `/work/[slug]`.

Both validate frontmatter at build time — a malformed entry **fails the build** with a precise message. Files starting with `_` (e.g. `_template.mdx`) never publish. Authoring: `cp _template.mdx my-entry.mdx` and edit.

- **Industries** (`src/lib/industries.ts`) — data-driven (not MDX) SEO landing pages targeting queries like "cosmetic surgery web design". Add an entry → a route renders automatically. Route: `/industries` + `/industries/[slug]`.
- ⚠ **BOTH data collections carry `heading` AND `seoTitle`, and they are different strings on purpose (2026-08-05).** `heading` is the H1's feature-benefit half; `seoTitle` is the `<title>`, the OG title, the **Service schema name** and the /industries index row label. They were ONE field, which meant conforming the masthead grammar would have silently rewritten the SERP titles and the structured data on the six highest-intent commercial routes on the site. **A masthead change must never cost a title tag** — when you edit an H1 here, check whether the target query still has a home. (The queries survive across the H1's two halves anyway: "Cosmetic Surgery" + "Web design that earns the consultation." still carries both terms, just once each instead of twice.)
- **Services** (`src/lib/services.ts`) — same data-driven pattern, added **2026-07-24 when /services SPLIT** into a hub plus one page per discipline (`/services/web-design`, `/services/seo`, `/services/brand-identity`). Three disciplines had shared one URL, so none could rank for its own queries ("medical website design", "medical SEO", "medical practice branding"). **Each service carries its OWN process**, which is the point of the split: the old combined page ran a *website* process ("schema, analytics and redirects") under a heading claiming five stages ran "every time", and a brand-only engagement never reaches those steps — so step counts now differ by discipline (web 5, SEO 4, brand 4). The hub's scroll-index rows are DERIVED from the same array (numeral, title, one-line lead, onward link only — the full paragraph and the dash-ruled deliverables moved to the detail pages), so hub and detail can't drift. FAQs are split by scope too: cross-discipline questions stay on the hub, per-discipline ones live on their own page, so no FAQPage schema repeats across routes.

MDX element styling lives in `mdx-components.tsx` at the repo root (`proseMdxComponents`), passed to `compileMDX` in the `[slug]` pages.

## Voice and copy

- **Restrained, editorial, considered.** No exclamation marks, no superlatives, no "transform your life" language. Taste signals competence in this market.
- **Titles never trade on comparison or disparagement (2026-07-16, sitewide).** The claim is always the studio's or the work's OWN focus — never an implied dig at other practices or other studios ("practices that take care seriously" implies others don't; both /about and /work have been rewritten off this pattern). H1s are SENTENCE CASE.
- **NEVER MENTION BRAND FIRST (2026-07-24, sitewide).** Wherever the disciplines are listed, the order is **web → search → brand**; brand is named last. The studio is website-led (see /about's own lede) and the client's 2026-07-14 call already put brand last in the services order ("I don't really want to do that service a lot"), so the copy has to agree with the architecture. This governs H1s, ledes, metadata descriptions, section copy and even image-credit alt text. Two consequences worth knowing: a masthead should lead on the WEBSITE and what it does for the practice, with search and brand arriving in the lede (the /services H1 was rewritten off "Brand, web and search: built to work as one." for exactly this); and the ONE sanctioned exception is the /about FAQ "What should a practice invest in first?", where "brand, then photography, then the website" is *advice about sequence* and the whole answer argues for that order. Positioning follows the rule; genuine sequencing advice is allowed to say what it means.
- **Dashes are swept from drafted copy.** Prefer colons, semicolons, commas and full stops; restructure the sentence rather than punctuating around it (the client's standing rule — see also docs/briefs/about-page.md).
- **Australian English** ("personalised", "specialise", "recognised").
- **UK-FIRST VOCABULARY, code excepted (2026-08-01, client's call on the hero graphic's schema panel).** Machine vocabulary stays American where the platform demands it — actual code, CSS `color`, real schema.org type names in real JSON-LD or in technical writing *about* the vocabulary (the schema blog post may name the `Physician` type). Everything else a reader sees is UK/Australian English: enquiry not inquiry, speciality not specialty, consultant surgeon never "board-certified physician". This governs DEPICTED code in graphics too — a marketing graphic showing schema picks UK-neutral vocabulary the spec actually offers (`MedicalClinic`, `PlasticSurgery`), never `Physician` (the services hero graphic was reworded off it). Logged on /stylesheet as the "UK first" house rule. ⚠ RESOLVED ON THE LIVE PAGE 2026-08-01: the v3 tile set replaced the graphics that carried "Board-certified facial surgeons" and the baked "+212%"; the old exports (`services-tile-search.avif`, `-seo-v2.avif`) stay on disk until sign-off and still carry those lines — do not wire them back in.
- **Regulatory caution.** Our clients work in regulated cosmetic medicine. In copy, don't name prescription (Schedule 4) substances or brand-name treatments — use generic terms ("injectables", "anti-wrinkle treatments"). Don't write claims a practice couldn't stand behind.
- The studio speaks as "we".

## Drift patterns to avoid

1. New `HeroX` instead of extending `PageHero` via props.
2. Bare `grid-cols-12` without `md:` — always `grid-cols-1 md:grid-cols-12` (mobile overflow).
3. Inline `clamp()` font sizes or `fontFamily` styles instead of the `.heading-*` / `.body-*` utilities.
4. Inline hex colours instead of `text-bone` / `bg-ink` / `text-champagne` etc.
5. Hand-rolled buttons instead of `.btn` + a variant.
6. A page with no exported `metadata`, or an empty `description`. This site is SEO-critical.
7. Adding structured data inline instead of via a `@/lib/schema` builder + `<JsonLd>`.
8. Rival scroll listeners instead of the `.reveal` / `<Reveal />` system.
9. Background gradients, glows or blobs — the ground is FLAT (2026-07-09). One scoped exception since 2026-07-16: the homepage craft card's dosed in-family gradient lives INSIDE its card, never on the ground — don't let it spread.
10. Radius freelancing (2026-08-01: WE ARE A ROUNDED BRAND) — imagery takes a PLATE token (`rounded-plate-sm/-plate/-plate-lg`; `.frame` has it), surfaces take a UI token (`rounded-ui-sm/-ui/-ui-lg`; `.card-soft`/`.card-glass` have it), never a raw `rounded-[...]`. Only cornerless things stay straight: hairline rules, underline-only inputs, tracked type (pills, bezels, avatars keep their own).
11. Champagne on label type (kickers, indices, stats) — gold is for details and interactions only.
12. Sizing headings by taste instead of THE LADDER's registers (see Typography).
13. Box-aligning side-by-side type (`items-center`/`items-end` alone) or `pt-*` nudges where a baseline lock belongs (see BASELINES LOCK).
14. Hover motion on imagery (scale/zoom) — plates don't swell; affordance is the caption dim and the gold arrow. And nothing auto-moves, ever.
15. Imagery at freelance aspect ratios — landscape is 16:10, portrait is 4:5, nothing else (device hardware, the OG card and logo marks excepted). Desktop captures are shot at 1440×900, never cropped to fit.
